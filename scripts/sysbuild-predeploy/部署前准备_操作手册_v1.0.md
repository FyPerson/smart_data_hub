## 2. Q7 结构版本与迁移

### 2.1 识别范围

| 结构版本 | 来源 | 业务表 / 索引 |
|---|---|---|
| V1 | C1–C3a；204bb3e6 / 546c1e93 同合约 | 40 / 58 |
| V2 | C3b；2822af79 | 41 / 64 |
| V3 | C4a–C4c；5a988b8c / 946e2e95 同合约 | 41 / 65 |
| V4 | C5；66831372 | 42 / 67 |
| V5 | C6a；1c590228 | 42 / 67 |
| V6 | C6b；8bbc6e78，本阶段目标合约 | 42 / 67 |

工具按完整标准形 SQL 的 SHA-256 识别，不能只凭表数量或账本声称的版本放行。模块独立账本 `sysbuild_schema_migrations` 是额外运维元数据，不计入上述42张业务表。账本首条须从 `from_version=0` 起步，表示此前没有版本账本，后续逐条承接前一条目标版本；实际识别的旧结构版本另写入迁移回执。

### 2.2 支持的动作

1. 没有 sysbuild 对象：显式初始化 V6并登记账本。
2. 已知旧结构、全部 sysbuild 业务表为空：完整备份后，在单个事务内重建空模块对象并登记版本。
3. 已是 V6且有业务数据：只登记版本，不覆盖业务行。
4. 已是 V6且账本一致：无操作，保持文件不变。

**P193 待裁建议**：有业务数据的旧结构、未知对象或触发器、版本账本断链或不一致均阻塞，输出原因和逐表数量，不猜测转换、不清数据。此限制适用于正式准备工具；实际生产是否有旧数据必须在用户在场时核实。

### 2.3 执行顺序

1. 按部署流程进入已正常停服的维护窗口。
2. `schema-inspect --db <已核实绝对路径> --report <新的报告绝对路径>`；只读检查，SQLite旁日志或WAL文件头在打开数据库前拒绝。阻塞报告的 CLI 退出码为2。
3. 检查 `sourceVersion`、`action`、`blocked` 与逐表数量；业务状态有疑义先处理映射规则。
4. 显式执行 `schema-apply --db <绝对路径> --backup-dir <既有备份目录> --expected-version <检查所得版本> --maintenance-confirmed --report <新的回执绝对路径>`。
5. 工具先生成自洽 SQLite 备份并核 SHA，随后在独占事务里复核 `data_version`、结构与数量；备份期间发生变化则拒绝迁移。事务内失败回滚，失败证据和备份保留。
6. 确认回执、账本、完整合约和平台原有数据保留结果，再进入部署流程的下一步。

报告目标已存在会在迁移前拒绝。迁移已提交而回执文件写入失败时，会明确返回 `applied: true` 与备份信息，须按账本核对实际状态。备份还原仍按部署流程单独确认，本工具不自动覆盖数据库。

在真实执行前，按规程7b对可信生产备份副本做检查与演练：确认真实结构和sysbuild行数；有数据的受支持结构保留1–3个真实项目作为核对样本，比较前后关键状态与数量；空旧结构明确记录0行。遇到非空旧结构或未知结构按P193阻塞，不转成“清空后通过”。2026-11-14已在11-11停服历史备份的私有副本完成检查、迁移与二次noop：来源V0、0个sysbuild对象，82张非模块表的完整结构与行数/内容摘要不变；sqlite_sequence中新增模块账本序号单列为预期变化，备份/账本/内外回执摘要一致，原备份不变。此证据仅证明该历史样本，不能替代当前生产来源版本、实际3002数据与真实只读DryRun的现场核对。

### 2.4 P195：显式部署接入建议

本版部署脚本增加 `-SysbuildMigrationFromVersion <0..6>`。来源版本须取用户在场审核过的最新真实样本检查结果；目标固定本版V6。按2026-11-12 D-1已定修法，新提交含项目管理模块时在生产写入前只读核对版本账本：无账本且漏带参数即拒绝；查询失败、截断或状态不明也拒绝。已有账本不代替真实样本版本核对；不含本模块的提交保留原部署路径。

接入点在原W10第6步代码切换之后、第7步服务启动之前：此时新工具、DDL与材料读取助手已在新提交中可用，服务已停且原全库备份已完成。停服前还会检查新提交包含迁移步骤文件。迁移步骤核显式来源与目标，完成后复核合约、账本和所有旧内容包材料引用；旧预留字段不兼容或冻结缺失只报告阻塞，不改写历史快照。

真实与演练结果共用协议分类器。来源、目标、合约摘要、兼容检查、回执路径 / SHA、已验证备份都须齐全才继续启动。结果为FAIL或UNKNOWN时写失败记录、保存诊断、输出人工恢复步骤，不自动起服务或回滚。`applied: null / outcome: unknown` 表示无法确认；`applied: true`即使后续报告或关闭失败也表示已提交，须按实际账本核对。

超时后的恢复前置新增只读迁移进程核查：查询成功且出现 `SYSBUILD_MIGRATION_PROCESS_SCAN_OK count=0` 才能继续人工恢复。此探针只在指南里给出命令，不会自动终止远端进程。原W10的全库备份 / rollbackTarget保持独立，不被模块备份覆盖。

本建议已在本版deploy-ssh.ps1、deploy-prestart.cjs及AST/Mock守卫中实现，仍待有效独立复审与用户在场采用；当前只做私有SQLite、可信历史备份副本与AST/Mock演练，没有执行真实部署或真实生产DryRun。存档只读修复的分包审查不包含部署实现时，须沿独立部署复审记录核结论，不能把分包未附源码当作未实现或已放行。

## 3. 3002 附件预存档与最终清单

### 3.1 存档口径

**P194 待裁建议**：保存所有物理附件原件，分别标记当前引用、历史引用、删除备份和未引用原件。一个物理文件对应一项核验记录，多个业务关联另列，避免重复计数。

清单包含项目、阶段、材料、原文件名、相对路径、大小、上传时间、SHA-256。未引用原件缺乏业务归属或上传时间时留空，不推断。JSON保存原始元数据，CSV对可能被表格软件解释为公式的文本加安全前缀。

索引指向的 `版本记录/*.json` 是当前提交依据；`project.json` 是镜像，可能在保存告警后落后。工具以提交快照为准并报告镜像状态。删除操作可推进全局工作区修订而保留未删除项目的旧快照，不能要求所有项目快照修订都等于全局修订。

遵守 D11：存档只包含附件和所需清单元数据，不复制项目过程正文、材料正文或原业务 JSON 记录。原记录不迁移到新模块。

### 3.2 预存档

1. 确认源目录为实际3002数据目录，存档目标在源目录之外且尚不存在。
2. 执行 `archive --source <绝对路径> --out <新存档目录> --phase prearchive`。
3. 工具独立只读扫描，不调用临时服务的 `createStore.read/init`，避免恢复删除记录的隐含写入。
4. 每项原件核大小 / SHA，复制后再核，随后复扫索引、快照与物理文件集合。源发生变化时只保留 `.partial-*`，不发布完整存档目录。
5. 将完整存档目录复制到经确认的本地保管位置，执行 `verify --archive <本地目录>` 核验。报告只称“预存档”。

### 3.3 只读开启后的最终清单

1. 按下一节部署并开启只读，核对 `/health` 的 `readOnly: true` 与新服务版本。
2. `capture-proof --base-url <已核实服务根地址> --expected-port 3002 --expected-version 0.8.0-readonly.2 --report <新的只读证明JSON>`；同时核URL端口和响应实际监听端口。端点只回工作区、修订、时间、服务版本、数据目录实路径、端口与只读标志，不保存业务正文。
3. `archive --source <绝对路径> --out <新的最终存档目录> --phase final --read-only-proof <证明JSON> --service-port 3002`。证明须为北京时间当天、同工作区与同修订、同源目录实路径、已审服务版本及已核实端口，不能用其它端口的副本或尚在24小时内的昨日证明。
4. `diff --before <预存档manifest.json> --after <最终manifest.json> --report <新的差异JSON>`；`fetch` 给出新增 / 变化原件，移除项单独列出，不自动删除本地旧文件。
5. 在新建的本地最终目录补齐原件。差异中的移除项移到存档目录外的独立留档区并记录摘要，保留原预存档；目录内使用服务器最终manifest及对应清单。以**服务器最终清单**核验：`verify --archive <本地最终目录> --manifest <最终manifest.json>`。文件数量、大小、SHA须全部相符；额外、缺失或变化均拒绝完整验收。失败的 `.partial-*` 由本轮执行人核对其路径、无活动导出/复制进程、证据已保存后单独处理，不清源目录或其它会话目录。

预存档不能替代最终清单。最终清单和证明作为当时的归档证据长期保管，后续删除原服务前仍用这一份清单核验本地原件。

## 4. 3002 只读服务准备

- 替换副本版本：`0.8.0-readonly.2`，与本包package.json一致。源文件原始SHA见 `temp-service/SOURCE.md`，在部署前核对原安装版本与这一份基准。
- 缺 `SYSBUILD_READ_ONLY` 默认只读；`1`只读，仅显式 `0`允许受控恢复写入。空文本及其它文本值拒绝启动。本包提供固化 `SYSBUILD_READ_ONLY: '1'` 的PM2配置；数据目录与端口在切换预览中逐项核实。
- 页面顶部显示“已切换到平台，只读”，保留查看、下载与重新读取；客户端拒绝写请求。
- HTTP所有非读取方法在解析 / 保存前403；存储层save/delete再次拒绝，覆盖整体保存中隐含的上传、替换与移除附件。
- 只读启动和读取不创建工作区、不恢复删除、不改索引或删除回执。原目录若有未完成且阻碍读取的事务，应在切换前按原流程核对；只读服务不会自行修复源数据。
- `/api/archive-proof` 只有只读状态才可用。旧可写页面在服务器切只读后也不能继续保存。

本轮只在私有数据目录与随机回环端口演练，没有访问、替换或重启实际3002服务。

### 4.1 用户在场的只读替换与固化

以下为切换机PowerShell操作清单，不由工具自动执行；须在发布/切换预览中列明实际安装目录、数据目录、原版本、备份目的地及文件摘要，经确认后实施。已记录的入口是 `E:\sysbuild-pm-temp`、数据 `E:\sysbuild-pm-data`、进程 `sysbuild-pm-temp`、端口3002；实际值须现场读回，不能据旧文档直接覆盖。

1. 完成预存档并核本地副本；等当前保存/删除事务结束，记录原health版本、PM2 pid及3002唯一监听pid。原只读数据若有未完成删除，不直接切换后反复重启。
2. `pm2 stop sysbuild-pm-temp` 后读回stopped；完整 `netstat -ano` 查询须成功且3002零LISTENING。把原 `server.cjs / server-client.js / offline.html / package.json / ecosystem.config.cjs` 复制到新建的本轮备份目录，分别核SHA并保留清单；不改数据目录。
3. 将本包这五个已核SHA的文件复制到已确认安装目录，保留原 `start-service.ps1`。新package版本与health同为 `0.8.0-readonly.2`，避免旧启动脚本拿旧package版本误判。检查新配置的cwd、dataDir、PORT和只读变量，再执行 `pm2 restart ecosystem.config.cjs --only sysbuild-pm-temp --update-env`；若返回失败则停下查实际状态，不盲用旧环境重启。
4. 核health的status/version/readOnly三项分别为ok、本版、true；核PM2 pid等于3002唯一监听pid。用§3.3新命令取证明，核端口、目录、版本和修订绑定后才 `pm2 save`，读回成功。原启动脚本只核status/version，不能代替readOnly核验或新的存档证明。
5. 生成并拉回当天最终清单，按最终清单核验原件。记录切换后所有写方法403；平台新入口与旧只读入口分别可达，补录和退役按后续条件处理。

回退：先核本轮本地/远端复制和重启命令均已结束，再停该进程并核3002零监听；从本轮精确备份恢复五个文件及原配置，按原版本起服务并核health、pid和目录。回到可写会重新开放旧入口写入，须单独由用户确认，不能在最终清单已验收后自动回退。原件/删除备份和业务记录不覆盖、不删除。

若只读启动发现未完成删除：保留现场，先核删除记录、索引与原件路径；经用户确认后仅本进程显式配置 `SYSBUILD_READ_ONLY=0` 运行一次既有恢复流程，核完成后重新停服，改回1、重启并重新核只读和当天证明，再固化PM2。不能把临时可写状态当作只读切换成功。

## 5. 切换后补录与退役

PM在平台按既定方案建项，附原始凭据恢复历史任职、授权、内容包与收口事实，历史确认与当前本人任务分开记录，保留原日期；关键附件从经最终核验的存档上传，完成后关闭历史补录窗口。
