# 通用字段标准

> 本文档定义数仓体系中各层公共字段的完整规格，是"查阅型"标准文档——回答"字段长什么样"的问题。
>
> **适用范围**: 所有纳入数仓体系的物理表。

---

## 一、审计字段

每张物理表**必须**包含对应层级的审计字段。审计字段使用 `dw_` 前缀，业务字段严禁使用此前缀。

### 1.1 ODS 层审计字段

核心问题：**"数据是哪天从哪个系统抽过来的？"**

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|------|
| `dw_load_ts` | DATETIME | NOT NULL | `GETDATE()` | 数据载入数仓的时间 |
| `dw_src_sys` | VARCHAR(20) | NOT NULL | - | 来源系统标识（如 BMS、HRD） |
| `dw_batch_id` | VARCHAR(20) | NOT NULL | - | ETL 运行批次号，格式 `YYYYMMDDHHmmss` |
| `dw_src_db` | VARCHAR(100) | NOT NULL | - | 来源数据库/表名 |

**dw_batch_id 格式规范**：
- 格式：`YYYYMMDDHHmmss`（14 位数字字符串），如 `20260202143000`
- 来源：FDL `${cyctime}` 参数经三层 REPLACE 转换
- 同一批次所有记录必须保持一致，**禁止使用 `GETDATE()` 作为批次号**

### 1.2 DWD 层审计字段

核心问题：**"这条记录是什么时候被加工出来的？"**

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|------|
| `dw_create_ts` | DATETIME | NOT NULL | `GETDATE()` | 记录在数仓中的生成时间 |
| `dw_update_ts` | DATETIME | NOT NULL | `GETDATE()` | 记录的最后更新时间（用于下游增量抽取） |
| `dw_etl_job` | VARCHAR(100) | NOT NULL | - | 加工脚本/任务名称（故障排查定位） |
| `dw_hash_val` | VARCHAR(64) | NULL | - | 全行字段 MD5 摘要（变更比对用） |

### 1.3 DIM 层审计字段

核心问题：**"这个属性现在还生效吗？"**

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|------|
| `dw_load_ts` | DATETIME | NOT NULL | `GETDATE()` | 数据载入时间 |
| `dw_src_sys` | VARCHAR(20) | NOT NULL | - | 来源系统标识 |
| `dw_batch_id` | VARCHAR(20) | NOT NULL | - | ETL 运行批次号 |
| `dw_update_ts` | DATETIME | NOT NULL | `GETDATE()` | 维度信息最后更新时间 |

### 1.4 审计字段通用规则

| 规则 | 说明 |
|------|------|
| 非空约束 | 所有 `dw_` 字段**必须** NOT NULL |
| 禁止篡改 | 严禁业务逻辑修改 `dw_` 字段，只能由 ETL 程序自动填充 |
| 显式声明 | 所有 INSERT 语句必须显式声明 `dw_etl_job` 的值 |
| 缺失即不可靠 | 缺失审计字段的表视为"不可靠资产"，禁止上线 |

## 二、SCD2 控制字段

DIM 层 SCD2（历史追踪）表的专用控制字段：

| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|------|
| `sk_{对象}` | BIGINT IDENTITY(1,1) | PRIMARY KEY | 自增 | 代理键（无业务含义） |
| `dw_eff_dt` | DATE | NOT NULL | - | 版本生效日期（等于变更发生日） |
| `dw_exp_dt` | DATE | NULL | `9999-12-31` | 版本失效日期（当前版本为 9999-12-31） |
| `dw_is_current_flg` | BIT | NOT NULL | - | 是否当前版本（1=是, 0=否） |
| `dw_is_initial_flg` | BIT | NOT NULL | - | 是否期初版本（1=是, 0=否） |
| `dw_hash_diff` | VARCHAR(64) | NOT NULL | - | 监控字段哈希值（变更检测用） |

**SCD2 数据约束**：
- 同一业务键，`dw_is_current_flg = 1` 的记录有且只有一条
- 当前版本的 `dw_exp_dt` 必须为 `9999-12-31`
- 版本链连续：前一版本的 `dw_exp_dt` = 后一版本的 `dw_eff_dt`

**平台配置说明**：
- 在智数协同平台中配置 DIM 模型时，只需指定**业务标识**（Business Key），代理键 `sk_{对象}` 会在 DDL 生成时自动创建
- 代理键命名规则：`sk_` + 业务标识字段名去掉 `_id` 后缀（如 `customer_id` → `sk_customer`）
- 代理键使用 IDENTITY(1,1) 自增，INSERT 时自动填充，无需在 ETL 脚本中手动指定

## 三、数据类型选型

### 3.1 标准类型对照

| 数据类别 | 标准类型 | 约束 | 示例 |
|---------|---------|------|------|
| 金额 | `DECIMAL(18,2)` | **严禁** FLOAT/DOUBLE | `salary_amt DECIMAL(18,2)` |
| 日期 | `DATE` | 仅日期，无时间部分 | `sign_dt DATE` |
| 时间戳 | `DATETIME` | 含日期和时间 | `dw_load_ts DATETIME` |
| 布尔值 | `TINYINT` 或 `BIT` | 取值 0/1 | `is_active_flg TINYINT` |
| 短字符串 | `VARCHAR(N)` | 长度按需分配 | `customer_name VARCHAR(100)` |
| 中文字符串 | `NVARCHAR(N)` | 含中文时使用 | `remark NVARCHAR(500)` |
| 长文本 | `NVARCHAR(MAX)` | 避免索引字段使用 | `audit_detail NVARCHAR(MAX)` |
| ID 类 | `VARCHAR` 或 `INT/BIGINT` | 超长编号用 VARCHAR | `id_card VARCHAR(20)` |
| 代理键 | `BIGINT IDENTITY(1,1)` | 自增主键 | `sk_customer BIGINT IDENTITY` |

### 3.2 类型红线

- 金额字段**严禁** FLOAT/DOUBLE（精度丢失）
- 避免盲目使用 TEXT/NTEXT（导致索引失效）
- 布尔值统一用 TINYINT/BIT + `_flg` 后缀，不用 BOOLEAN（跨库兼容）
- ODS/DWD 字符串字段长度建议为源表的 **1.5~2 倍**（预留扩容空间）

## 四、NULL 值处理标准

对可能出现的 NULL 值，必须进行 `COALESCE` 或 `ISNULL` 容错处理：

| 数据类型 | 默认填充值 | 示例 |
|---------|-----------|------|
| 字符串 | `'Unknown'` 或 `'-'` | `ISNULL(customer_name, 'Unknown')` |
| 数值（金额/计数） | `0` | `ISNULL(order_amt, 0)` |
| 数值（ID 类） | `-1` | `ISNULL(category_id, -1)` |
| 日期 | `'1900-01-01'` | `ISNULL(sign_dt, '1900-01-01')` |

## 五、审计日志字段标准

### 5.1 dw_audit_log 表字段

公共审计日志表 `dbo.dw_audit_log` 的标准字段定义：

| 字段名 | 数据类型 | 约束 | 说明 |
|--------|----------|------|------|
| `audit_id` | BIGINT IDENTITY(1,1) | PRIMARY KEY | 自增主键 |
| `table_name` | VARCHAR(128) | NOT NULL | 目标表名 |
| `data_layer` | VARCHAR(10) | NULL | 数据层级（ODS/DIM/DWD/DWS/ADS） |
| `record_key` | NVARCHAR(500) | NULL | 业务键 JSON |
| `audit_type` | VARCHAR(20) | NOT NULL | 审计类型（见下表） |
| `audit_level` | VARCHAR(10) | NOT NULL | 级别（INFO/WARN/ERROR） |
| `audit_detail` | NVARCHAR(MAX) | NULL | 变更详情 JSON（before/after 快照） |
| `diff_fields` | NVARCHAR(500) | NULL | 差异字段摘要 |
| `source_table` | VARCHAR(128) | NULL | 来源表名 |
| `biz_date` | DATE | NULL | 业务日期 |
| `affected_count` | INT | NULL | 受影响记录数 |
| `is_resolved` | BIT | NOT NULL DEFAULT 0 | 是否已处理 |
| `resolved_by` | VARCHAR(50) | NULL | 处理人 |
| `resolved_at` | DATETIME | NULL | 处理时间 |
| `resolve_comment` | NVARCHAR(500) | NULL | 处理说明 |
| `batch_id` | VARCHAR(50) | NULL | ETL 批次号 |
| `created_at` | DATETIME | NOT NULL DEFAULT GETDATE() | 创建时间 |

### 5.2 audit_type 枚举值

| 值 | 级别 | 含义 | 写入场景 |
|----|------|------|----------|
| `DELETED` | WARN | 源表已删除，dim 表对应记录被关闭 | DIM FDL Step 1 删除检测 |
| `MODIFIED` | INFO | 同一业务键的字段值发生变化 | DIM FDL Step 2 修改检测 |
| `INSERT` | INFO | 新增记录插入 dim 表 | DIM FDL Step 3 新增检测 |
| `REBUILD` | INFO | 版本链自动修复 | DIM FDL Step 4 版本链重建 |
| `INCONSISTENT` | ERROR | dim 当前版本与主表不一致 | DIM FDL Step 5 一致性告警 |
| `MERGE` | INFO | SCD1 增量 MERGE 操作 | DIM 增量更新脚本 |
| `CLOSE_VERSION` | INFO | SCD2 增量关闭旧版本 | DIM 增量更新脚本 |
| `INSERT_VERSION` | INFO | SCD2 增量插入新版本 | DIM 增量更新脚本 |
| `LATE_ARRIVAL` | WARN | 迟到数据 | 预留 |
| `DUPLICATED` | ERROR | 重复数据检测 | 预留 |
| `ROLLBACK` | WARN | 回滚操作 | 预留 |
| `FULL_REFRESH` | INFO | 全量刷新 | 预留 |

### 5.3 audit_level 含义

| 级别 | 含义 | 处理方式 |
|------|------|---------|
| `INFO` | 正常业务变更 | 自动记录，无需处理 |
| `WARN` | 需关注的异常 | 建议人工确认 |
| `ERROR` | 必须处理的告警 | 必须人工处理并标记 `is_resolved` |

## 六、DIM 层标准索引

DIM 表建表时必须包含以下标准索引：

| 索引名模式 | 字段 | 用途 |
|-----------|------|------|
| `IX_{表名}_bk` | 业务键 | 业务键查询（ETL 关联） |
| `IX_{表名}_current` | 业务键 + `dw_is_current_flg` | 当前版本快速查询 |
| `IX_{表名}_eff` | `dw_eff_dt` + `dw_exp_dt` | 版本时间范围查询 |
