# 分层标准

> 本文档定义数仓体系的分层架构与数据流转规则，是"查阅型"标准文档——回答"数据放哪层"的问题。
>
> **适用范围**: 纳入公司数仓体系的所有数据对象。

---

## 一、分层架构总览

```
源系统(BMS/CRM等) → FDL同步 → ODS → DWD → DWS → ADS → 应用
                                  ↓
                                 DIM (维度表供各层使用)
```

| 层级 | 全称 | 定位 | 数据特征 |
|------|------|------|----------|
| **ODS** | Operational Data Store | 贴源层 | 与源系统结构一一对应，不做业务逻辑处理 |
| **DIM** | Dimension | 维度层 | 维度主数据，支持 SCD，相对稳定 |
| **DWD** | Data Warehouse Detail | 明细层 | 按业务过程建模，最细粒度，完成清洗标准化 |
| **DWS** | Data Warehouse Summary | 汇总层 | 按主题域汇总，支持上卷下钻 |
| **ADS** | Application Data Store | 应用层 | 面向报表/BI/数据产品，高度定制化 |

---

## 二、各层定义

### 2.1 ODS 层（贴源层）

| 属性 | 定义 |
|------|------|
| **数据来源** | 源系统（BMS、CRM 等）通过 FDL 同步 |
| **表结构** | 与源系统一一对应 |
| **处理逻辑** | 仅做字段类型适配，不做业务逻辑处理 |
| **更新策略** | 默认日全量快照（Truncate & Reload），大表增量合并 |
| **命名规范** | `ods_{表名}_df` |

### 2.2 DIM 层（维度层）

| 属性 | 定义 |
|------|------|
| **数据来源** | 主要来自 ODS 层，可能关联多张源表和字典表 |
| **SCD 支持** | SCD1（直接覆盖）和 SCD2（历史版本追踪） |
| **更新频率** | T+1 批量更新 |
| **质量要求** | 高（下游 DWD/DWS 层依赖） |
| **命名规范** | `dim_{业务对象}` |

### 2.3 DWD 层（明细层）

| 属性 | 定义 |
|------|------|
| **建模驱动** | 以业务过程（Business Process）为驱动 |
| **数据粒度** | 最细粒度，保持明细，**严禁不可逆聚合** |
| **处理逻辑** | 数据清洗、去重、标准化、关联维度形成宽表 |
| **更新策略** | 全量覆盖（`_df`）或增量追加（`_di`） |
| **命名规范** | `dwd_{业务域}_{业务对象}_{更新周期}` |

### 2.4 DWS 层（汇总层）

| 属性 | 定义 |
|------|------|
| **建模驱动** | 以分析主题为驱动 |
| **数据粒度** | 按不同粒度聚合 DWD 层数据 |
| **用途** | 提供常用的汇总指标，支持上卷下钻分析 |
| **命名规范** | `dws_{主题}_{粒度}_{周期}` |

### 2.5 ADS 层（应用层）

| 属性 | 定义 |
|------|------|
| **服务对象** | 报表、BI、数据产品 |
| **特点** | 高度定制化，查询性能优先 |
| **数据来源** | DWS/DWD 层 |
| **命名规范** | `ads_{应用场景}_{内容描述}` |

## 三、流转规则

### 3.1 核心原则

| 原则 | 说明 |
|------|------|
| **单向流转** | 数据只能从低层流向高层：ODS → DWD → DWS → ADS |
| **禁止跨层** | 严禁 ADS 层直接调用 ODS 层原始数据 |
| **高内聚低耦合** | 业务逻辑应尽量在 DWD 层沉淀 |
| **铁律** | 所有指标必须基于 DWD 事实表计算，**严禁直连 ODS** |

### 3.2 DIM 层特殊规则

DIM 层不参与层级流转链，而是作为**公共维度**供各层使用：

- ODS → DIM（维度加工）
- DWD 层关联 DIM（维度扩展）
- DWS/ADS 层关联 DIM（维度查询）

### 3.3 数据流向图

```
┌─────────────────────────────────────────────────────────────┐
│                                                               │
│  源系统 ──→ ODS ──→ DWD ──→ DWS ──→ ADS ──→ 报表/BI       │
│              │                                                │
│              └──→ DIM ←──────────────── 供各层关联使用        │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

## 四、层级判定速查表

在设计阶段参考下表决定数据落层，实现"事前判断"而非"事后返工"：

| 场景问题 | 建议层级 | 判定说明 |
|---------|---------|---------|
| 需要保留源系统原始数据？ | **ODS** | 贴源保存，不做业务加工 |
| 一行等于一次业务事件？ | **DWD** | 事实表，保持明细粒度 |
| 仅描述实体属性（非事件）？ | **DIM** | 维度表，需判断 SCD 类型 |
| 需要还原历史状态？ | **DIM (SCD2)** | 关键属性必须保留历史 |
| 涉及跨域金额汇总？ | **DWS** | 严禁在 DWD 层做跨域聚合 |
| 面向特定报表或应用？ | **ADS** | 高度定制，查询优先 |
| 指标计算能否绕过 DWD？ | **NO** | 铁律：必须基于 DWD 计算 |

## 五、域边界判定

采用 Kimball 维度建模的**业务过程**作为域划分依据：

> 一张表属于哪个域，取决于它记录的是哪个业务过程的事实，而不是它引用了哪个实体。

| 判定条件 | 归属 | 示例 |
|---------|------|------|
| 表的粒度就是该业务实体本身 | 该实体所在域 | 合同主表 → 合同域 |
| 表描述的是该实体的属性或组成部分 | 该实体所在域 | 合同付款计划 → 合同域 |
| 表描述的是另一个业务过程，但引用了该实体 | 另一个业务过程所在域 | 开票记录引用合同 → 财务域 |

## 六、更新策略标准

### 6.1 ODS 层

| 策略 | 适用场景 | 实现方式 |
|------|---------|---------|
| 日全量快照 | 数据量可控（建议参考值 < 5000万行） | 每日 Truncate & Reload |
| 增量合并 | 超大数据量流水表 | 基于 `update_time` 增量合并 |

### 6.2 DWD 层

| 策略 | 后缀 | 适用场景 |
|------|------|---------|
| 日全量覆盖 | `_df` | 实体表（当前默认策略），每日 TRUNCATE + INSERT |
| 增量追加 | `_di` | 变更记录、流水日志等只增不改的表 |

**主表 + 变更快照组合**：对需要追踪变更历史的主表，采用"全量覆盖主表 + 增量变更快照表"的组合。

### 6.3 DIM 层

| SCD 类型 | 策略 | 适用场景 |
|---------|------|---------|
| SCD1 | 直接覆盖 | 数据纠错、不关心历史的属性 |
| SCD2 | 新增版本 | 需要回溯历史变更的关键属性 |
