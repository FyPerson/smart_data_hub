# 命名标准

> 本文档定义数仓体系内所有对象的命名规则，是"查阅型"标准文档——回答"叫什么"的问题。
>
> **适用范围**: 纳入公司数仓体系的所有表、字段、指标、临时对象。

---

## 一、表命名

### 1.1 标准格式

```
{层级}_{业务域}_{业务对象}_{更新周期}
```

| 段 | 说明 | 约束 |
|----|------|------|
| 层级 | 数据层级前缀 | 必须从下方层级前缀表中选取 |
| 业务域 | 公司注册的业务域简称 | 必须从下方业务域注册表中选取（DWD/DWS/ADS 必填，ODS/DIM 可省略） |
| 业务对象 | 表所描述的业务实体或过程 | 不得与业务域名称语义重复 |
| 更新周期 | 更新策略后缀 | 见下方更新周期缩写表 |

### 1.2 层级前缀

| 前缀 | 层级 | 说明 |
|------|------|------|
| `ods_` | 贴源层 | 保持与源系统结构高度一致 |
| `dim_` | 维度层 | 组织架构、员工主数据、业务字典等 |
| `dwd_` | 明细层 | 按业务过程建模 |
| `dws_` | 汇总层 | 按主题域汇总 |
| `ads_` | 应用层 | 按具体报表/应用命名 |

### 1.3 业务域注册表

| 简称 | 业务域 | 英文全称 | 注册日期 |
|------|--------|----------|----------|
| cont | 合同 | Contract | 2026-01-29 |
| bid | 招投标 | Bidding | 2026-01-29 |
| pub | 公共 | Public | 2026-01-29 |
| fin | 财务 | Finance | 2026-01-29 |
| proj | 项目 | Project | 2026-01-29 |
| dlvr | 交付 | Delivery | 2026-01-29 |

> 新增业务域时，在本表追加注册即可。简称建议 3-4 个字母，见名知意。
> 权威来源：[ADR-001 §2](/Doc_Viewer.html?file=docs/decision/ADR-001_DWD层通用开发约定.md)

### 1.4 更新周期缩写

| 后缀 | 含义 | 适用场景 |
|------|------|----------|
| `_df` | 日全量 (Daily Full) | 数据量可控的实体表（默认策略） |
| `_di` | 日增量 (Daily Incremental) | 变更记录、流水日志等只增不改的表 |
| `_1d` | 日粒度汇总 | DWS 层日汇总 |
| `_1m` | 月粒度汇总 | DWS 层月汇总 |

### 1.5 各层命名示例

| 层级 | 命名模式 | 示例 |
|------|----------|------|
| ODS | `ods_{表名}_df` | `ods_contract_df`、`ods_base_data_item_df` |
| DIM | `dim_{业务对象}` | `dim_customer`、`dim_organization` |
| DWD | `dwd_{域}_{对象}_{周期}` | `dwd_cont_header_df`、`dwd_fin_payment_df` |
| DWS | `dws_{主题}_{粒度}_{周期}` | `dws_trade_store_1d` |
| ADS | `ads_{场景}_{描述}` | `ads_fin_monthly_report` |

> **ODS 特别说明**：当前数据源均来自单一业务系统（BMS），ODS 表名不包含系统前缀。若后续接入多个独立源系统，可增加系统标识以区分。

### 1.6 临时与备份对象

| 类型 | 格式 | 示例 |
|------|------|------|
| 临时表 | `tmp_{业务描述}_{yyyymmdd}` | `tmp_cust_fix_20260202` |
| 备份表 | `bak_{原表名}_{yyyymmdd}` | `bak_dwd_order_20260202` |

> 临时表需定期清理，备份表用于重大变更前备份。

### 1.7 命名红线

- **严禁**出现无层级前缀的"孤儿表"
- **严禁** DWD 表的业务对象与业务域名称语义重复（错误示例：~~`dwd_cont_contract_detail_di`~~）
- 表名变更**必须**同步更新数据字典

## 二、字段命名

### 2.1 字段后缀标准

| 后缀 | 含义 | 数据类型 | 示例 |
|------|------|----------|------|
| `_amt` | 金额 | DECIMAL(18,2) | `salary_amt`、`contract_amt` |
| `_dt` | 日期 | DATE | `enter_dt`、`sign_dt` |
| `_ts` | 时间戳 | DATETIME | `dw_load_ts`、`dw_update_ts` |
| `_flg` | 标志（布尔） | TINYINT / BIT (0/1) | `is_active_flg`、`dw_is_current_flg` |
| `_sts` | 状态 | VARCHAR | `contract_sts` |
| `_id` | 标识/编号 | INT / BIGINT / VARCHAR | `customer_id`、`dw_batch_id` |
| `_cnt` | 计数 | INT | `order_cnt` |
| `_rate` | 比率 | DECIMAL | `conversion_rate` |
| `_pct` | 百分比 | DECIMAL | `completion_pct` |

### 2.2 命名原则

- 字段名应具备**自解释性**：看到 `_amt` 即知是金额，看到 `_sts` 即知需要查对应的状态映射
- 使用 **snake_case**（小写 + 下划线）
- `dw_` 前缀保留给审计/控制字段，业务字段**严禁**使用 `dw_` 前缀

## 三、指标命名

### 3.1 五段式结构

```
[前缀]_{业务对象}_{动作/修饰}_{度量/原子}_{时间周期}
```

| 段 | 说明 | 示例 |
|----|------|------|
| 前缀 | 可选，仅特殊场景 | `derived_` |
| 业务对象 | 指标所属实体 | `cust`、`ord`、`emp` |
| 动作/修饰 | 业务过程或状态 | `pay`、`cancel`、`active` |
| 度量/原子 | 计算口径缩写 | `amt`、`cnt`、`rate` |
| 时间周期 | 统计窗口 | `1d`、`7d`、`mtd`、`ytd` |

### 3.2 示例

| 指标中文名 | 解析 | 标准英文名称 |
|-----------|------|-------------|
| 过去7天签约金额 | cont + sign + amt + 7d | `cont_sign_amt_7d` |
| 员工入职总数 | emp + enter + cnt | `emp_enter_cnt` |
| 客户活跃标志 | cust + active + flg | `cust_active_flg` |

### 3.3 指标命名红线

- 后缀严格遵循本文档定义：金额=`_amt`，数量=`_cnt`，标志=`_flg`，比率=`_rate`
- 新指标注册前**必须**检索字典，严禁同名不同义
- 重大口径变更须新建指标（如 `_v2`），严禁覆盖历史
- 废弃指标须标记 `[DEPRECATED]`

## 四、DWD 表族命名模式

同一业务域的 DWD 表构成一个"表族"，遵循以下命名模式：

| 角色 | 命名模式 | 示例 |
|------|----------|------|
| 主事实表 | `dwd_{域}_{实体}_{周期}` | `dwd_cont_header_df` |
| 变更快照表 | `dwd_{域}_{实体}_change_di` | `dwd_cont_header_change_di` |
| 关系/衍生表 | `dwd_{域}_{关系描述}_{周期}` | `dwd_cont_renew_chain_df` |
| 跨域桥接表 | `dwd_{域}_{关系}_bridge_df` | `dwd_fin_cont_bridge_df` |

> 详见 [ADR-001 §7 表族管理约定](/Doc_Viewer.html?file=docs/decision/ADR-001_DWD层通用开发约定.md)
