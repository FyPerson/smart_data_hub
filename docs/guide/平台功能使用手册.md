# 智数协同平台 - 功能使用手册

> **版本**: v1.112.1
> **更新日期**: 2026-07-12
> **适用对象**: 数据开发人员、业务对接人、项目管理员

**阅读说明**：本文档中的界面示意图用于说明功能布局和操作流程，具体样式以实际页面为准。文档中出现的按钮文案、必填项、字段名均以代码实际实现为准核实过；如页面后续迭代导致个别细节变化，以页面实际显示为准。

## 一、平台概览

### 1.1 技术平台

本平台配套的数据仓库技术栈如下：

| 组件 | 技术 | 说明 |
|------|------|------|
| **数据仓库** | SQL Server | 目标数仓，存储各层数据表 |
| **数据同步** | FineDataLink (FDL) | 帆软数据集成工具，负责 ETL 调度 |

平台生成的脚本（DDL、ETL）均基于 SQL Server 语法，同步脚本可直接用于 FDL 节点配置。

平台自 2025 年 10 月启动建设，采用原生 HTML/CSS/JS 前端（多个独立页面 + 共享组件层）+ Node.js/Express + SQLite 后端，PM2 部署在内网 192.168.1.100，访问地址 http://192.168.1.100:3000。

### 1.2 功能模块导航

顶部导航栏从左到右依次为：**数仓任务池 / 数据协作 / 数据开发 / 数据修正 / 系统迭代 / 数据中心（下拉）/ 统计中心 / 文档中心**；管理员在右上角头像下拉菜单里还能看到「周期取数推送」「用户管理」两个专属入口。

| 模块 | 入口文件 | 功能定位 |
|------|----------|----------|
| 数仓任务池 | Task_Pool.html | 数据团队内部数仓开发任务的发布、认领、提交、归档（原"任务池"，v1.111 起改名，操作逻辑不变） |
| 数据协作 | Data_Collab.html | 业务方临时取数需求主入口：建单、指派、开发交付、验收归档，详见第三章 |
| 数据开发 | Issue_Tracker.html | 数据开发需求单登记与跟踪（原"问题跟踪/需求跟踪"，v1.111 起改名），详见第五章 |
| 数据修正 | Data_Correction.html | 业务系统数据修正申请闭环，详见第四章 |
| 系统迭代 | Sys_Iteration.html | 平台自身功能迭代与 bug 修复闭环，详见第六章 |
| 建设总览 | Dashboard.html | 数仓建设进度看板（数据中心下拉，也是登录后首页） |
| 资产中心 | Asset_Center.html | 数据资产目录（数据中心下拉） |
| 模型中心 | Model_Center.html | ODS/DIM/DWD 模型管理（数据中心下拉），详见第七、八章 |
| 指标中心 | Metrics.html | 业务指标定义与管理（数据中心下拉），详见第九章 |
| 统计中心 | Statistics.html | 团队工作量与流转统计 + 四模块效率统计，详见第十章 |
| 文档中心 | Doc_Viewer.html | 规范文档在线阅读，详见第十一章 |
| 周期取数推送 | Periodic_Fetch.html | 月度固定取数模板化 + 钉钉推送（仅管理员），详见第十二章 |
| 用户管理 | admin.html | 用户账号管理 + 数据库连接配置 + 钉钉应用配置（仅管理员），详见第十三章 |

> **注意**：原"个人工作台"（My_Workspace.html）已从导航下线，详见附录 FAQ。业务域配置（Domain_Manager.html）作为管理员的辅助工具，仍可从用户管理页面顶部按钮跳转，未单独列入主导航。

### 1.3 用户角色

平台的登录账号有 4 种系统角色，权限随角色固定；而"对接人""开发"等身份是各协作类模块里**按单据临时指定的业务流转角色**，不是独立的登录权限——同一个账号可能在这张单上是对接人，在另一张单上是开发。

| 系统角色 | 权限范围 | 典型使用者 |
|------|----------|----------|
| **管理员（admin）** | 全部功能：用户管理、数据库连接与钉钉应用配置、周期取数推送；数据协作/数据修正/系统迭代的建单与验收归档；各模块单据的批量操作与物理删除 | 平台管理员，各新模块单据的最终验收人 |
| **发布者（publisher）** | 数仓任务池发布任务；数据开发需求登记与指派 | 数据团队负责人、需求统筹 |
| **开发者（user，默认账号类型）** | 认领/开发/交付各模块分配给自己的任务与单据；哪些操作按钮可见取决于具体单据当前状态和分配对象 | 数据开发人员 |
| **查看者（viewer）** | 只读浏览，隐藏发布类入口（如数仓任务池的"发布新任务"区域和"我的工作台"相关链接） | 只读旁观账号 |

> **对业务对接人/业务方的说明**：数据协作、数据修正等模块里的"对接人"由管理员建单时从系统用户下拉中指定，负责在业务方和开发之间转派、沟通、拉群；提需求的"业务方"本人通常不登录平台，只以姓名+手机号留痕，进度通过钉钉工作通知触达，需要时也可以由对接人在钉钉群里同步。

## 二、数仓任务池

### 2.1 数仓任务池

**入口**: 导航栏 → 数仓任务池 或直接访问 `Task_Pool.html`（原"任务池"，v1.111 前端统一改名，页面内部的操作逻辑、URL、任务类型均未变化）

#### 流程指引面板

页面顶部有**流程指引面板**（可折叠），分为两种角色视角：

| 角色 | 流程步骤 |
|------|----------|
| **开发者** | 领取任务 → 模型注册/确认 → 开发调试 → 提交验收 |
| **发布者** | 模型规划 → 发布任务 → 进度跟踪 → 验收审核 |

> 点击「模型注册/确认」步骤可直接跳转到模型中心。如果任务已关联模型，可跳过此步骤。

## 三、数据协作

### 3.1 模块定位

**入口**: 导航栏 → 数据协作 或直接访问 `Data_Collab.html`

数据协作是业务方临时取数需求的主入口，全流程为：管理员录入需求单 → 指派对接人 → 对接人转派开发 → 开发交付脚本和数据 → 平台自动跑 SQL Smoke Test 校验 → 任一方可拉钉钉群沟通 → 管理员验收归档。详情页以**右侧抽屉**形式展开，点击列表行即可查看，不会跳转到新页面。

涉及的角色：

| 角色 | 在本模块里做什么 |
|------|----------|
| 管理员 | 建单、通知对接人、验收、归档/作废 |
| 对接人 | 转派/改派开发、和业务方沟通、查看进度 |
| 开发 | 上传脚本与数据交付物 |
| 业务方 | 通常不登录平台，姓名+手机号留痕，进度靠钉钉通知和拉群同步 |

### 3.2 建单（管理员操作）

点击「新建协作单」（仅管理员可见），填写以下信息：

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| OA流程号 | 必填 | 只需填数字部分，系统自动补全为"OA-xxxxx"形式的单号 |
| 需求部门 | 必填 | 下拉选择 |
| 业务方负责人姓名 | 必填 | |
| 业务方负责人手机号 | 选填 | 用于后续钉钉拉群时匹配到具体的人 |
| 需求描述 | 必填 | |
| 期望完成时间 | 必填 | 日期时间选择器 |
| 目标业务库 | 必填 | 下拉选择要取数的源库连接 |
| 对接人 | 必填（勾选"admin 直派模式"可跳过） | 从系统用户中选择，负责后续转派开发、和业务方沟通 |
| 原始单据截图 | 选填，可传多份 | 最多 5 个文件，支持 png/jpg/gif/webp/pdf，单文件不超过 10MB |
| 数据模板 | 选填 | 单文件，xlsx/xls，不超过 10MB |
| 数据范围说明 | 选填，可传多份 | xlsx/xls/txt，各不超过 10MB，最多 5 个 |

> **注意**：管理员建单时可以勾选"🎯 admin 直派模式"，跳过对接人环节直接指定开发，适用于需求本身已经很明确、不需要业务对接的场景。直派单在列表和详情页会带"admin 直派"标记，不显示"对接人"这一行。

### 3.3 指派与转派（对接人环节）

1. 建单后单据进入"待指派开发"状态，管理员可以点击「通知对接人」（已经通知过会显示「重新通知」）推送钉钉工作通知给对接人；这个动作只是发通知，不会改变单据状态。
2. 对接人（或管理员）在详情页点击「指派开发」，从系统用户下拉里选一名开发人员——下拉会列出全部活跃用户，不能选对接人本人。
3. 指派完成后单据进入"待开发"状态。如果需要换人，再次点击「改派开发」重新选择即可。

### 3.4 开发交付

开发在详情页点击「上传交付物」（已经传过会显示「重新上传交付物」），脚本文件和数据文件是**两个独立的上传入口**：

| 交付物 | 格式 | 数量与大小限制 | 说明 |
|------|----------|----------|------|
| SQL 脚本 | .sql / .txt | 最多 5 个，单文件不超过 1MB | 第一份脚本会跑 Smoke Test，其余作为附带交付物 |
| 结果数据 | .xlsx / .xls | 最多 5 个，单文件不超过 100MB | 第一份参与列对齐校验 |

#### SQL Smoke Test（提交时会遇到什么）

开发提交的第一份 SQL 脚本要先通过平台的 4 层防御校验（语法解析 / 关键字黑名单 / 只读校验 / 真连业务库试跑），通过才算交付成功。常见被拦下的原因：

| 情形 | 平台会提示 |
|------|----------|
| 脚本首个关键字不是 SELECT/WITH（比如写了 UPDATE/INSERT） | 本平台只接收只读查询脚本，不执行写操作 |
| 出现 EXEC、xp_/sp_ 等存储过程调用 | 检测到禁用关键字/扩展存储过程 |
| 用 SELECT INTO 建临时表 | Smoke Test 不允许 DDL 操作 |
| 跨库查询目标库以外的表 | 跨库引用不允许，仅允许目标库内的表 |
| 使用了临时表 #tmp | 请改用 CTE 或子查询 |
| 使用了 UNION 或 OFFSET/FETCH 分页 | 暂不支持，请改写为单个 SELECT |

> **注意**：不需要手动给查询加 TOP/LIMIT——脚本没写限制时，平台会自动注入 TOP 100/LIMIT 100，避免大表全量拉取拖垮业务库；脚本如果写了多余的 ORDER BY，平台也会在试跑时自动剥离，不需要开发自己删。

### 3.5 钉钉拉群

- 详情页「拉起讨论群」按钮，管理员、对接人、开发三方**任一**都可以点。
- 点击后会弹出确认框（写明协作单号），确认后建群。
- 建群成功会提示"沟通群已建立，请到钉钉客户端查看消息列表"，之后按钮位置会显示已建的群名。
- 单据归档或作废后，这个区块会整体隐藏。

### 3.6 验收与归档

1. 开发交付完成后单据进入"已提交"，管理员核对脚本和数据无误后点击「归档」。
2. 归档确认框可以填写备注，点击「确认归档」后单据进入"已归档"，之后是只读历史状态——开发不能再修改或重传交付物，只有管理员可以继续操作。
3. 如果单据不需要处理了，管理员可以点击「作废」（红色按钮），需要二次确认；作废后单据从列表消失，只有勾选"显示已作废"筛选才能找到，且**不可恢复**。

> **注意**：归档单/作废单的历史通知记录会保留、以只读方式展示——各通知区块标题会标注"（记录）"字样，只展示"已通知/已读"的既成事实，不再出现「重新通知」「通知业务方并发送数据」这类可以再次发送的按钮。这是 v1.112 版本统一的规则，数据协作、数据修正、数据开发、系统迭代四个模块的终态单据都遵循同一原则。

### 3.7 查询已读

对接人、开发、业务方三处通知区块都配有一个「查询已读」按钮，点击可以查询对方是否已读该条钉钉通知；一旦查到已读，会直接固化展示"📖 姓名 已读 · 于 时间"，不用重复点。

### 4.2 建单（管理员操作）

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| OA流程号 | 选填 | 只填数字（1-20 位），留空则系统按"信息技术部自发现"处理 |
| 流程类型 | 选填 | 文本输入框，不是固定下拉，可自由填写涉及的业务系统/审批流程名称 |
| 修正类型/修正方式 | 必填 | 描述"哪里的什么数据错了、要改成什么" |
| 所属系统 | 必填 | |
| 原因/背景 | 必填 | |
| 业务方部门 | 必填 | 下拉选择（如市场营销部、交付运营部、财务管理部等） |
| 主业务方姓名 | 填了真实 OA 号时必填 | 可以加多行，第一行为主业务方 |
| 期望完成时间 | 选填 | |

### 4.3 单据类型说明

| 类型 | 界面标识 | 说明 |
|------|----------|------|
| 普通单 | 无特殊标识 | 默认类型 |
| 批量数据修正单 | 建单表单里选"批量数据修正"，需额外填"修正条数"（≥2） | 一张单据记录一次批量修正涉及的条数，不是逐条录入，完成时填一段"批量完成说明" |
| 返工单 | 红色左边条，返工子单额外带红底 | 不能直接新建，只能对已归档单点「重新打开返工」生成子单 |

### 4.4 完成留证规则

| 单据类型 | 完成说明 | 截图 |
|------|----------|------|
| 普通单 / 批量单 | 必填，不少于 5 个字 | 选填 |
| 返工子单 | 必填，不少于 5 个字 | **必填**，页面会有红字提示"返工双必填" |

### 4.5 归档流程

数据修正没有独立的"复核"角色和"通过/打回"两段式审核，流转方式是：

1. 修正完成后，单据进入"已完成/已重修"状态，管理员或建单人可以直接点击「确认归档」。
2. 如果业务方对结果有异议，可以先拉群沟通，再走「重修提交」重新修正一次，不是走"打回"。
3. 建单还没开始处理前（待指派/待回复预计/修正中状态），管理员或建单人可以点击「拒绝修正单」，拒绝的是这次诉求本身，不是审核已完成的修正结果。
4. 单据归档后如果确实需要再改，通过「重新打开返工」生成一个返工子单，其余流程按钮基本不再显示。

### 4.6 通知

数据修正有 5 类钉钉通知场景：开发、对接人、业务方（预计完成时间）、业务方（完成）、建单人，**都需要在详情页手动点击对应按钮触发**，归档动作本身不会自动发通知。如果操作人和建单人不是同一人，标记完成时会弹窗询问是否顺带通知建单人。每类通知都配有「查询已读」按钮，已读后固化展示"通知于 X · 已读于 X"。

## 六、系统迭代

### 6.1 模块定位

**入口**: 导航栏 → 系统迭代 或直接访问 `Sys_Iteration.html`

系统迭代管理平台自身的迭代闭环，覆盖新功能、优化、缺陷（bug）、配置变更四类单据；新功能/优化/配置变更走"变更流"，缺陷走"bug 流"，两条路径不同，最终都通过"上线批次"统一管理上线节奏。建单目前仅管理员可操作，需求方/报障人信息由管理员在建单时代填（部门、姓名、手机号），暂时没有面向普通用户的自助报障入口。

### 6.2 四类单据

| 类型代码 | 界面标签 | 适用场景 |
|------|----------|----------|
| feature | 新功能 | 全新模块或能力 |
| improvement | 优化 | 已有功能的改进 |
| bug | BUG | 缺陷修复 |
| config | 配置变更 | 参数/配置类调整 |

### 6.3 变更流（新功能 / 优化 / 配置变更）

建单 → 排期 → 指派 → 回填预计完成时间 → 可行性评估（仅新功能/优化类型需要）→ 提交交付 → 验收通过 → 上线（走发版或 hotfix）。

### 6.4 bug 流

管理员建单时，可以选三种指派路径之一：

1. **指定主开发**——负责整张 bug 单的状态流转，可以同时选择协作开发。
2. **只指定通知对接人**——目前对接人范围较小（白名单式），不进入常规状态机，只做知会。
3. **暂不指派**——留待后续处理。

"协作开发"是可以多选的辅助角色，只收钉钉通知、不参与状态机流转，页面上会有明确提示"协作开发仅收通知、不参与状态机流转"，用于知会需要了解进度但不负责修复的相关人员。bug 流后续同样要经过修复 → 验收 → 上线编排（指定/更换执行开发 → 执行上线）。

### 6.5 上线批次与批量通知

- 「批次管理」由管理员创建，一个批次可以把多张"待上线"的单据打包在一起统一发布；bug 批次只能收 bug 单，变更批次只能收新功能/优化单，两类不能混批。
- 批次标题/编号可以留空由系统自动生成，也可以手动填写。
- 「批量指定上线开发」「批量通知上线开发」「批量执行上线（发版）」三个批量操作按钮，批量通知前会弹出确认框，写明"同执行人多单合并一条钉钉"，避免同一个人因为多张单同时上线收到好几条重复通知；发送后会展示"成功 X / 失败 Y / 已变更 Z"的结果汇总。

### 6.6 物理删除（管理员操作）

详情页危险操作区提供「删除任务」按钮，仅管理员可见。点击后弹出二次确认框，明确写"此操作不可恢复，将一并清除该单的状态历史、附件、协作开发、四方通知记录"。如果该单已经派生出子单（比如已经进过批次等关联场景），会被直接拦截并提示"该单已派生出子单，不可删除"。

## 十二、周期取数推送（仅管理员）

### 12.1 模块定位

**入口**: 右上角头像下拉菜单 → 周期取数推送 或直接访问 `Periodic_Fetch.html`（仅管理员可用，前端和后端都会校验角色，非管理员访问会被拒绝）

周期取数推送面向需要每月固定跑一批取数的场景：把常用的周期性取数 SQL 登记成模板，模板里用占位符表示"上月区间"，每月只需点一下就能按新的时间窗口重新跑数，跑完可以直接通过钉钉把结果 xlsx 推送给业务方。

### 12.2 登记取数模板

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| 任务名称 | 必填 | |
| 说明 | 选填 | |
| 目标业务库 | 必填 | 下拉选择已配置的只读连接 |
| 模板脚本 | 必填 | SQL 内容里用 `{{MONTH_START}}` / `{{MONTH_END}}` 表示时间区间的起止（按 Asia/Shanghai 时区计算"上月整月"，左闭右开）；表单提供"点击插入"按钮直接把占位符写进脚本，旁边有提示"上月首日含、本月首日不含" |

保存模板时平台会做基本语法校验，防止脚本里混入多条语句或写操作（如 EXEC、增删改语句）。

### 12.3 跑数

点击「跑本月」按钮，平台按 Asia/Shanghai 时区自动换算成"上月"区间执行查询。跑数为全量查询，但有硬约束：**行数上限 10 万行、超时 60 秒**，超过限制会直接判定失败，不会做隐式截断。每次跑数的记录都保留在"跑数·历史"表格里，可以看到执行时间、日期区间、行数、耗时、状态。

### 12.4 推送前收件人核对

1. 收件人按"姓名,手机号"逐行录入，一批最多 20 个。
2. 点击「核对可送达」，平台反查每个手机号对应的钉钉账号是否可达：可送达显示绿色"钉钉可送达"及钉钉ID后四位；查不到或存在多个匹配会显示红色"禁发"及原因。
3. 姓名由管理员自己录入，平台只核对手机号对应的钉钉账号是否存在，**不会反查姓名是否匹配本人**，录入时要自行核对准确性。
4. 核对通过后勾选需要推送的收件人，点击「确认发送给已勾选的收件人」才会真正推送。
5. 如果本次跑数结果是 0 行（空结果），推送前需要额外勾选一次"确认仍要推送空结果"。

### 12.5 推送 xlsx

确认推送后，平台把选中的那次跑数结果打包成 xlsx 文件，通过钉钉发送给已勾选的收件人，推送完成后会提示"成功 X / 失败 X / 跳过 X"的汇总结果。

> **注意**：周期取数推送涉及真实业务数据外发，务必先核对收件人身份和推送范围，确认无误后再点击推送。

## 十三、系统管理

### 13.1 用户管理

**入口**: 右上角头像下拉菜单 → 用户管理 或直接访问 `admin.html`（仅管理员可见此入口）

**权限要求**: 仅管理员可访问

#### 功能清单

| 功能 | 说明 |
|------|------|
| 用户列表 | 查看所有用户账号 |
| 新建用户 | 创建新账号，设置角色（管理员/发布者/开发者/查看者），可选填手机号（协作通知用）和备注 |
| 重置密码 | 没有独立的"重置密码"按钮，通过「编辑」用户信息弹窗里的"新密码"栏设置，留空则不修改原密码 |
| 禁用/启用 | 账号状态管理，列表每行按当前状态显示对应的操作按钮 |

### 13.2 数据库连接管理

**入口**: 用户管理页面（`admin.html`）→「数据库连接配置」区块（原"模型中心 → 设置"入口已合并到用户管理页面）

#### 连接类型

| 类型 | 用途 |
|------|------|
| **数仓连接** | 目标数据仓库（用于验收、DDL 执行） |
| **源系统连接** | 业务系统数据库（用于字段获取、数据对比） |

### 13.3 钉钉应用配置

**入口**: 用户管理页面（`admin.html`）→「钉钉配置」区块

管理员可以在用户管理页面配置钉钉应用凭证（AppKey/AppSecret）、单聊机器人 RobotCode 等参数，用于支撑数据协作、数据修正、数据开发、系统迭代四个模块的钉钉工作通知、拉群和已读回执功能。已配置过的密钥字段以 `***` 显示，留空或保持 `***` 不会改写原值。

### B. 常见问题

| 问题 | 解决方案 |
|------|----------|
| 原来的"个人工作台"去哪了？ | v1.111 前端统一改造中已从导航下线（页面文件保留，但导航入口已摘除，使用率低，团队内部决策下线）。如需查看和自己相关的任务，仍可以在数仓任务池、数据协作等各模块的列表里直接查看。 |
| "OA流程号"要怎么填？ | 只需要填数字部分，系统会自动补成"OA-xxxxx"的单号展示；不同模块对是否必填的要求不一样（如数据协作建单必填，数据修正建单选填、留空按"信息技术部自发现"处理），以对应建单表单上的提示为准。 |
| SQL Smoke Test 常见拒绝原因有哪些？ | 常见的是脚本第一个关键字不是 SELECT/WITH、用了临时表/UNION/跨库查询等，详见"三、数据协作 3.4 开发交付"里的对照表；不需要手动加 TOP/LIMIT，平台会自动限制到 100 行。 |
| 单据归档以后还能看到通知记录吗？ | 能。归档/作废后的单据里，历史通知和已读记录会保留、以只读方式展示，只是不再出现可以重新发送的按钮。 |
| 系统迭代里"主开发"和"协作开发"有什么区别？ | 主开发负责整张 bug 单的状态流转（是状态机意义上的责任人），协作开发是辅助角色，只会收到钉钉通知，不影响单据状态。 |
| 模型编辑按钮无响应 | 检查是否为该模型的负责人 |
| 验收失败：表不存在 | 先在数仓执行 DDL 建表 |
| 派生字段表达式报错 | 检查关联表别名是否正确 |
| 页面加载缓慢 | 尝试刷新页面或清除浏览器缓存 |
